0.执行摘要

项目一句话

DB-GPT 是一个以「组件系统 + AWEL DAG 工作流引擎 + 多 Agent 框架」三大抽象为骨架的平台型项目：连接数据库/文件/知识库，让 AI 自主编写 SQL 与代码并执行分析，生成图表与报告。后端 Python（FastAPI）+ 前端 Next.js 13，采用 uv workspace monorepo（7 个包，依赖链 dbgpt-app → dbgpt-serve → dbgpt-ext → dbgpt(core)）。

2.2 AWEL（Agentic Workflow Expression Language）工作流引擎

位置：packages/dbgpt-core/src/dbgpt/core/awel/。RAG 管线、多 Agent 编排、模型调用全部以 AWEL 算子拼装。

DAG 与连边

  • DependencyMixin 重载 >>/<< 运算符连边；with DAG("x") as dag: 上下文内创建的算子经 DAGVar（双栈：异步 ContextVar / 同步 threading.local）自动挂入该 DAG。
  • DAG._build() 重算根/叶/触发节点。执行顺序由 Runner 从叶节点深度优先回溯（DAG 自身不做拓扑排序；唯一的 Kahn 排序在 FlowFactory，用于资源实例化顺序与环检测）。
  • DAGContext 每次触发生成一个：node_to_outputs（节点输出共享表）+ share_data（带锁的旁路数据，仅单次触发内有效，非持久化）。

算子体系

算子机制二开要点
MapOperator单输入变换最常用：重写 async def map(self, input_value)
JoinOperatorcombine_function 合并多上游多输入解包为位置参数传入
BranchOperator/Joinbranches: Dict[谓词, 目标节点名]；未命中分支标记 SKIP_DATA目标用节点名（FlowFactory 里是 task_name=operator_key）；BranchJoinOperator 不跳过
Streamify/Unstreamify/TransformStream值↔流变换三件套流式变换全部惰性（迭代前不消耗数据）
HttpTrigger 等DAG 入口，动态注册 FastAPI 路由（前缀 /api/v1/awel/trigger）CommonLLMHttpRequestBody 是聊天类应用的统一入口协议

元类魔法：BaseOperatorMeta 在子类定义时自动注入默认参数（dag/system_app/executor/runner）并调用 after_define() —— 类一旦声明了 metadata: ViewMetadata 属性即自动注册进全局 FlowRegistry（UI 节点面板数据源）。前提：模块必须被进程 import。

执行器（asyncio 模型）

  • DefaultWorkflowRunner._execute_node：深度优先递归执行上游（当前串行，并行是 TODO）；同一节点一次触发只执行一次（命中缓存即返回）。
  • 流式场景的 after_dag_end 收尾挂在 HttpTrigger 的 BackgroundTasks，不在 runner 里——自定义调用 call_stream 时注意（钩子需幂等）。
  • 约束：HttpTrigger 与 chat flow 都要求 DAG 恰好一个叶节点。

声明式 DSL（UI 拖拽编排）

  • flow/base.py：Parameter/IOField/ViewMetadata/ResourceMetadata + @register_resource/@auto_register_resource（后者只支持 dataclass，字段自动转参数）。运算符/资源/触发器类型枚举：OperatorCategory/OperatorType/ResourceCategory。
  • FlowFactory.build(flow_panel)：JSON → 可运行 DAG。节点分桶 → 边处理（资源连入算子参数位置）→ Kahn 拓扑排序 → 按序实例化资源与算子 → with DAG(...) 连边（有 mapper 的边自动插入转换算子）。安全起见用注册表元数据而非前端传来的元数据。
  • Flow 存储：dbgpt_serve_flow 表（flow_data 存 JSON 字符串）+ 变量表 dbgpt_serve_variables（secret 用 Fernet 加密）；服务前缀 /api/v1/serve/awel，GET /nodes 供前端节点面板。

3.2 ConversableAgent 执行循环（base_agent.py，1460 行）

generate_reply（@final，不可覆写，只能覆写钩子）主循环 = while retry < max_retry_count：

① Think
LLM 调用，3 次重试 + 模型 failover（失败排除该模型再选）→ ② Review
人审/策略钩子，默认直通→ ③ Act
多 Action 链式，parse_action 可做协议路由→ ④ Verify
approve + 执行成功 + 非空 + correctness_check→ ⑤ 失败：observation 回注下一轮
  • 熔断三要素：max_retry_count（默认 3；ManagerAgent=1；ReActAgent=30）× max_timeout（600s）× ActionOutput.have_retry（False 直接终止重试）。
  • 模型选择：LLMStrategyType.Priority + strategy_context（JSON 优先级列表）；失败 sleep(10) 排除失败模型重试。二开必改 无可用模型时兜底硬编码返回 "deepseek-chat"（base_agent.py:1202）。
  • run_mode：DEFAULT（成功一次即停）/ LOOP（成功后继续循环直到 terminate）——ReAct 类 agent 的实现方式。
  • 流式：底层总是走 generate_stream，差分出 delta_text/delta_thinking；stream_out=True 时实时推入 GptsMemory vis 队列 = 前端打字机效果。
  • 异常兜底：任何异常返回 AgentMessage(success=False) 不抛出，保证团队循环不被单 agent 打断。
  • 上下文超长：捕获含 context_too_long 的错误 → 触发响应式压缩后重试一次。

3.4 上下文预算管理（类似 Claude Code 的 context compaction）

默认预算 max_context_tokens=120000、预留 4096、警告 0.70 / 错误 0.90 / 危急 0.95。四层渐进压缩：

层触发策略
L1 ObservationMicroCompact≥WARNING5 轮之前的 Observation 截断到 500 字符
L2 SessionMemoryCompact≥WARNING按 ReAct 三元组划分轮次，丢弃旧轮（保留最近 3 轮且 ≥10000 token）；依赖 {{ task_progress }} 做隐式摘要，无 LLM 调用
L3 FullContextCompression≥ERRORLLM 六段式摘要（原任务/已完成/现状/关键数据/错误/下一步）替换旧消息
L4 ReactiveCompactLLM 报上下文超限紧急只保留 system + 最近 2 轮

配套防线：工具结果持久化——单结果超 10 万字符自动落盘（persisted_results/），上下文替换为 1500 字符预览 + read_file 回读；每次成功动作后写操作快照（op_snapshots/step_NNN.json）并维护 task_progress 注入系统提示。状态事件以 __CONTEXT_STATUS__ 前缀进 SSE，消费端需识别。

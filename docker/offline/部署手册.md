# K-ICS 现场离线部署手册

适用版本：20260909，Linux x86_64，客户现场完全离线。

## 1. 准备条件

- 宿主机已安装并启动 Docker Engine，管理员有 Docker 操作权限；不需要 Compose。
- 建议预留至少 20 GB 可用磁盘，另按上传文件和知识库规模规划数据盘。
- 平台不运行本地模型，LLM 和 Embedding 使用现场已有服务，不要求平台主机有 GPU。
- 单个分析沙箱限制为 1 GB 内存、2 CPU、128 个进程；并发分析需另预留资源。
- 准备客户网关 appKey、appSecret、CA 证书，以及 Oracle 用户名和密码。
- 宿主机时间准确，应用容器能够访问以下内网服务。

| 服务 | 地址 | 配置 |
| --- | --- | --- |
| LLM 网关 | https://10.146.16.36:8898/aiApi/workflow/llmProxy | qwen3.8_27b |
| Embedding | http://10.84.97.104:8000/v1/embeddings | Qwen3-Embedding-0.6B |
| Oracle 11.2.0.4 | 172.16.176.154:1530 | Service Name：LSRSDB |

平台元数据使用 SQLite，向量数据使用本地 Chroma，无需另装 MySQL、PostgreSQL
或向量数据库。业务 Oracle、LLM 和 Embedding 不包含在镜像中。

本包已在 Docker 29.1.3、Linux 6.12 的 x86_64 主机验证；客户麒麟 4.19
内核及其 Docker 版本仍需实际验收。Docker 安装程序不在交付包中。

## 2. 获取并校验交付包

构建服务器：192.168.8.37。交付目录：

```text
/opt/kics-build-20260909/dist/
```

将以下文件通过现场允许的介质传入目标主机同一目录：

- k-ics-offline-20260909-linux-amd64.tar，约 1.7 GB。
- k-ics-offline-20260909-linux-amd64.tar.sha256。
- 本部署手册。

在文件所在目录执行：

```bash
sha256sum -c k-ics-offline-20260909-linux-amd64.tar.sha256
mkdir -p /opt/k-ics
tar -xf k-ics-offline-20260909-linux-amd64.tar -C /opt/k-ics
cd /opt/k-ics/k-ics-offline-20260909-linux-amd64
sha256sum -c SHA256SUMS
docker version
docker load -i images.tar.gz
docker image inspect k-ics:20260909 k-ics-python:20260909 >/dev/null
```

两次校验均应显示 OK。现场不需要下载基础镜像，也不需要安装 Python、Node、
UV 或 pip 依赖。保持部署目录位置固定，沙箱需要使用该目录的绝对路径。

## 3. 配置凭据和证书

后续命令均在部署目录执行：

```bash
cp site.env.example site.env
chmod 600 site.env
mkdir -p certs
vi site.env
```

填写以下两项，保留模板其他内容：

```dotenv
SITE_APP_KEY=填写客户appKey
SITE_APP_SECRET=填写客户appSecret
```

此文件由 Docker 的 `--env-file` 读取：每行 `名称=值`，不写 `export`，
不额外加引号，不在值后写行尾注释。不要将真实凭据加入源码或镜像。

把客户 CA 链文件放到 `certs/customer-ca.pem`，并在 site.env 追加：

```dotenv
SITE_CA_FILE=/app/certs/customer-ca.pem
```

证书必须匹配网关 URL 中的 IP 或主机名。如果证书签发给域名，应使用正确的
域名 URL，并确保容器内可以解析。仅在受控测试中，可将 site.toml 中
`verify_tls = true` 改为 `false`；此时还需移除 SITE_CA_FILE 配置。

默认模型名和服务地址已写入 site.toml。需要覆盖地址时，可在 site.env 追加：

```dotenv
SITE_LLM_MODEL=qwen3.8_27b
SITE_LLM_URL=https://10.146.16.36:8898/aiApi/workflow/llmProxy
SITE_EMBEDDING_URL=http://10.84.97.104:8000/v1/embeddings
```

appKey、rt、SM3 sign 由平台逐次生成，用户无需手工计算签名。

## 4. 启动平台

仅在主机本地访问：

```bash
bash start.sh
```

需要局域网访问时，将下面示例 IP 替换为部署主机实际内网 IP：

```bash
KICS_BIND_ADDRESS=192.168.8.37 KICS_PORT=5670 bash start.sh
```

KICS_BIND_ADDRESS 和 KICS_PORT 是启动脚本的环境变量，不能仅填写到 site.env。
端口被占用时可改为 15670；后续访问地址也相应修改。

```bash
docker logs --tail 100 k-ics
docker ps --filter name=k-ics
```

默认本机绑定模式下检查：

```bash
curl -f http://127.0.0.1:5670/api/health
```

返回 `{"status":"ok"}` 表示平台健康接口正常。如果绑定了指定内网 IP，
上述 URL 应改为该 IP。浏览器访问 `http://部署主机IP:5670`。
按现场要求配置防火墙和管理入口访问范围。

启动脚本不会自动替换同名容器。发现 `k-ics` 已存在时，先确认其用途，
按第 7 节维护步骤处理，不要直接删除不明容器。

## 5. 添加 Oracle 数据源

在平台的数据源管理界面新建 Oracle 数据源，填写：

| 字段 | 值 |
| --- | --- |
| 类型 | Oracle |
| 主机 | 172.16.176.154 |
| 端口 | 1530 |
| 连接标识类型 | 服务名 / Service Name |
| service_name | LSRSDB |
| SID | 留空 |
| 用户名、密码 | 现场提供的数据库账号 |

不要填写开发隧道地址 127.0.0.1:11530。对应 JDBC 语义为
`jdbc:oracle:thin:@//172.16.176.154:1530/LSRSDB`，平台实际使用 python-oracledb
和已打包的 Oracle 19.32 Thick 客户端，不依赖 JDBC 驱动。

先测试连接，再保存并验证表结构、字段注释和查询结果。
数据库账号需要具备目标业务表的读取权限。

## 6. 验收

1. 首页和健康接口正常。
2. 普通对话、流式对话均能收到客户网关结果；模型名为 qwen3.8_27b。
3. Embedding 接口可用，知识库或数据库摘要索引正常建立。
4. Oracle 连接、表结构读取和简单只读查询正常，中文内容显示正常。
5. 上传 Excel 后执行统计和绘图，能取得结果文件和图表。
6. 检查分析结束后没有遗留沙箱容器：

```bash
docker ps -a --filter label=kics.role=analysis-sandbox
```

不要在有其他分析任务执行时，将正常运行中的沙箱误判为残留容器。

构建阶段已完成 63 条回归测试和断网容器验证，详情见 VALIDATION.md 与
smoke-results.txt。真实现场账号、内网服务和麒麟环境仍需按上述步骤验收。

## 7. 停止、重启、改配置和备份

```bash
docker stop k-ics
docker start k-ics
docker logs --tail 200 k-ics
```

修改 site.env 后，单纯 restart 不会更新容器环境，需重建平台容器：

```bash
docker stop k-ics
docker rm k-ics
bash start.sh
```

原先使用内网 IP 或自定义端口时，最后一条命令应带上原来的
KICS_BIND_ADDRESS 和 KICS_PORT。数据存储在宿主部署目录，删除平台容器不会
删除这些绑定目录。不要删除 data 目录。

一致性备份应先停止平台，再打包数据和配置：

```bash
docker stop k-ics
tar -czf ../k-ics-backup-$(date +%Y%m%d-%H%M%S).tar.gz data site.env site.toml certs
docker start k-ics
```

备份包含凭据和业务数据，应按现场要求保管。恢复时停止平台，在原部署路径
恢复对应数据和配置，再启动。更换版本前保留旧镜像和数据备份。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 启动提示 image 不存在 | 重新执行 docker load，确认两个镜像标签完全一致 |
| 端口占用 | 检查已有服务，调整 KICS_PORT，不停止其他业务容器 |
| 浏览器无法访问 | 检查是否使用了默认 127.0.0.1 绑定、主机防火墙和实际端口 |
| 网关鉴权失败 | 检查 appKey/appSecret、宿主机时间和实际模型名 |
| HTTP 200 但模型报错 | 查看日志中的客户业务错误码；200 不一定表示模型调用成功 |
| TLS 验证失败 | 检查 CA 链、容器路径、证书有效期及域名/IP 匹配 |
| Embedding 连接失败 | 确认容器到 10.84.97.104:8000 的网络、模型名和服务状态 |
| Oracle ORA-12514 | 核对服务名 LSRSDB 和监听器服务注册信息，不要改填 SID |
| Oracle ORA-01017 | 核对数据库用户名、密码和账号状态 |
| Oracle DPI-1047 | 确认运行交付镜像及 ORACLE_THICK_MODE=true，检查客户端加载日志 |
| 沙箱创建失败 | 检查 Docker socket 挂载、沙箱镜像、宿主磁盘和数据目录绝对路径 |
| 新技能缺少 Python 包 | 在联网构建环境补依赖并重新导出镜像，现场不在线安装 |

## 9. 执行边界

平台通过宿主 Docker socket 创建独立分析容器，应部署在受信任主机上。
分析容器本身不挂载 Docker socket、不接收网关凭据、禁用网络，根文件系统只读。
输入文件只读挂载，当前分析输出目录可写。

旧 Lyric 脚本和 AWEL Lyric 路径在 Docker 模式下拒绝执行；Notebook、浏览器
自动化和 GPU 执行不在交付范围内。更换为标准 OpenAI 服务时，按 README.md
替换完整 LLM 配置块，删除客户网关专用参数，使用 proxy/openai。
